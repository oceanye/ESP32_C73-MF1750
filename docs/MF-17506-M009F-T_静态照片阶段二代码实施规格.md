## 1. 目标与边界

本轮代码的产品目标不是继续追求动态刷新，而是建立一条可重复的**静态照片制作链**：

1. 用已采购的 24 色卡校正“相机 + 光源 + 拍摄设置”形成的测量偏差；
2. 在 factory-OTP 波形下标定“前态码 → 最终码”产生的有效外观；
3. 把合格的历史状态记录成可审计的“配方调色板”；
4. 将任意静态照片离线转换为 `Primer` 和 `Target` 两张 4 bpp 帧；
5. 先输出电脑预览和完整证据包，现场程序只执行已冻结的双帧配方；
6. 正常显示期间不频繁切继电器，最终成像后可安全断电并依靠电子纸保持画面。

本轮明确不包含：

- 不把 24 色卡当成分光测色仪，也不宣称得到计量级绝对色度；
- 不把相机照片中的混合色宣称成新单像素颜料色；
- 不把 code 4/7 或历史亮度状态塞进现有严格六码 `Palette`，从而破坏白色保护和物理码语义；
- 不默认重跑已经失败的 Atkinson、multicolor-DBS 或 face-smooth B 真屏动作；
- 不实现或开放阶段三 RAM-LUT 写入；G3/G4 未通过时保持代码级硬阻塞；
- 不在继电器型号、协议和失联行为未知时猜测真实 adapter。

照片能更可靠地比较，并把实测有效外观反馈给静态照片渲染器。

## 4. 24 色卡校正功能

### 4.1 色卡资料入库

需要为所购色卡建立一个 `CHART-SPEC.json`，至少包含：

- 品牌、准确型号、序列号或批次（如果有）；
- 6×4 或实际 patch 排列、方向标记和 patch 名称；
- 厂家提供的 Lab/XYZ/sRGB 参考值及其光源、观察者条件；
- 参考资料文件 SHA-256、来源说明和录入人；
- `reference_grade`：`vendor_reference`、`batch_measured` 或 `layout_only`。

若厂家没有可靠参考值，系统仍可做跨照片的会话归一化，但输出必须标为
`CAMERA_RELATIVE`；只有有明确参考值时才允许标为 `REFERENCED_CALIBRATION`。两者都不能冒充
分光仪测量。

### 4.2 拍摄合同

每个测量会话固定：

1. 色卡与面板尽量处在同一平面、同一光照下，并同时进入画面；
2. 相机固定位置、焦距、曝光、ISO、白平衡和对焦；关闭 HDR、滤镜和 AI 场景增强；
3. V1 接收 JPEG/PNG；保留 ICC 并转 sRGB。RAW 支持作为后续可选 adapter，不阻塞首版；
4. 每个时间点拍 3 张不改变设置的照片，用中位数抵抗手抖和局部反光；
5. 保存原图，不覆盖、不二次压缩；A4 白纸只用于干净背景和检查阴影；
6. 在工具中人工给出色卡四角和面板四角；自动识别延后，避免现场误识别仍继续分析。

### 4.3 校正模型

V1 采用保守、可解释的模型：

1. 将输入 sRGB 解码到线性 RGB；
2. 先由中性 patch 检查曝光、通道剪裁和白平衡；
3. 用 24 patch 鲁棒拟合带偏置的 `linear RGB → XYZ` 变换；
4. 转换到 D65/2° Lab，输出每个 patch 的 ΔE00；
5. 同时报告拟合内误差和 leave-one-patch-out 误差，避免只看过拟合后的好成绩；
6. V1 不使用高阶多项式，后续只有证据表明确有必要才增加模型复杂度。

校正硬门：色卡方向明确、24 patch 全部在图内、无大面积通道剪裁、patch 内部方差不过限、
三张照片的几何与曝光一致。ΔE00 初期作为报告值，不在不知道色卡型号和相机样张时先拍脑袋
写死阈值；拿到第一组样张后再冻结合格阈值。

输出：

```text
CAMERA-CALIBRATION.json
chart-rectified.png
chart-annotated.png
patch-measurements.csv
residual-summary.json
```

## 5. 首轮优先测试：16 个蓝色历史配方

现有 8×8 先导证据只在 target code 4/7 的列观察到随 source 改变的蓝色亮度，尚未发现新的
稳定色相。因此静态照片方向不先重复全部 42 pair，而是先把最有使用价值的 16 个配方定量化：

```text
source 0..7 → target 4    共 8 项
source 0..7 → target 7    共 8 项
```

批次 A：左半屏放 8 个 `→4`，右半屏放 8 个 `→7`。  
批次 A′：左右控制器和区域顺序镜像，使每个配方都在另一控制器/位置复测。

每批固定三个可见动作：

1. `Primer`：16 格各写自己的 source transport code；
2. `Target`：对应格写 code 4 或 code 7；
3. `White`：标准恢复并确认无残留。

两批合计 **6 个可见动作**。5 s、60 s、10 min 的拍照不算刷新动作。正常批次内保持上电，
不在 Primer 和 Target 之间切继电器。

### 5.1 首轮判断

程序为每格输出：

- 校正 Lab、L*、a*、b* 和最近参考色 ΔE00；
- 三张照片内部一致性、patch 均匀性和纹理指标；
- 5 s → 60 s → 10 min 的漂移；
- A 与 A′ 的控制器/位置差；
- code 4 与 code 7 同 source 的差异；
- Target 之前的 Primer 身份、帧 hash、固件和 factory-OTP 身份；
- 白恢复是否合格。

首轮只产生 `H0/H1/H2/H3` 候选分类，不直接写入生产调色板。

### 5.2 配方资格化

只有 H2 配方才进入：

- 至少 10 次重复；
- 0.5/2/10/60 s dwell；
- 1 h/24 h 保持，`powered_idle` 与 `safe_power_off` 分开统计；
- 两个控制器、中心/边缘位置复核；
- 标准白恢复检查。

配方是否纳入静态照片调色板，取决于重复性、保持、位置一致性和可恢复性；不能仅凭“颜色看起来
更丰富”或一张照片入库。若 16 项最终只是若干可重复的蓝色亮度，也照样有使用价值，但名称应是
“有效蓝色亮度状态”，不是“新颜料色”。

### 5.3 从大色块到照片像素的桥接测试

大色块有效不等于 1 像素棋盘中仍然有效。正式用于照片前，候选配方需要追加 1/2/4/8 px
空间周期和纯大块的同屏比较，检查邻域耦合、颗粒感和可见纹理：

- 1 px 有效才允许逐像素配方；
- 1 px 不稳定但 2/4 px 有效时，渲染器只能用相应最小 recipe cell；
- 只有大色块有效时，只能用于大面积区域或图形，不进入通用照片像素调色板。

这道门用于避免把大块蓝色亮度差错误地外推到高频抖动照片。

## 6. `HISTORY-PALETTE.json` 设计

每个有效外观不是一个裸颜色码，而是完整配方：

```text
recipe_id
primer_transport_code
target_transport_code
primer_dwell_ms
target_repeat_count
factory_profile_id
temperature_band_c
retention_mode
minimum_recipe_cell_px
measured_lab + preview_rgb
within_patch_uniformity
repeat_delta_e00
controller_delta_e00
retention_delta_e00
recovery_qualified
measurement_artifact_sha256
qualification_level
```

强制规则：

- transport code 允许 0..7，但它与原六码 physical palette 是不同类型；
- 每个测量值必须反向绑定相机会话、原始照片、ROI、帧、固件和观察记录；
- 温度或保持模式不匹配时，渲染器默认拒绝，而不是静默套用；
- code 4/7 是否合并由实测 ΔE00 与重复结果决定，不预先假定；
- 未资格化、恢复失败、出现 BUSY/电流异常的 recipe 不能进入可执行候选。

## 7. 静态照片渲染器

### 7.1 输入与输出

输入为 JPEG/PNG 静态照片、合格的 `HISTORY-PALETTE.json`、目标温度/保持 profile 和裁剪参数。
图像先按现有规则完成 ICC→sRGB、方向纠正和 1024×600 cover/contain。

每个候选包固定输出：

```text
source-original.*
source-normalized.png
modeled-final.png
primer-preview.png
target-code-preview.png
comparison-contact-sheet.png
primer.bin
target.bin
RENDER-MANIFEST.json
```

`modeled-final.png` 用实测 Lab 显示预计最终外观；`target-code-preview.png` 只显示最终 transport
code，不能替代历史配方预览。两个 `.bin` 必须各为 307,200 bytes，并分别保存 full-frame、
CS1 和 CS2 的 SHA-256/FNV。

### 7.2 首版四种离线候选

同一照片一次生成四个候选供人工比较，不直接选一个上屏：

| 模式 | 目的 | 首版定位 |
|---|---|---|
| `nearest-recipe` | 最低颗粒，接受色阶分段 | 平滑优先基线 |
| `ordered-bayer-8x8` | 可重复、有规则的空间混色 | 风景/色块基线 |
| `smooth-cluster` | 在局部面积内保持比例并限制孤立噪点 | 静态照片重点新方案 |
| `edge-aware-diffusion` | 保边缘和细节 | 对照项，不继承旧 Atkinson 为默认 |

`smooth-cluster` 的首版合同是“局部面积比例正确、最小连通块受控、边缘单独保护、输出完全确定”，
而不是硬编码某张人脸的椭圆皮肤区。人物、风景和蓝色渐变各用一张固定验收图，防止算法只对某类
照片好看。

历史配方与空间抖动分两级放行：先证明每个 recipe 可重复，再证明 recipe cell 在所选尺寸有效，
最后才允许组合。若历史调色板没有合格项，渲染器仍可生成传统六码离线预览，但必须标注
`BASE_PALETTE_ONLY`。

### 7.3 人工选择门

预览包生成后，用户选择确切候选 ID。该选择只冻结双帧和 manifest，不等于真屏授权。后续若需
真屏，必须另建 session release；不允许程序依据评分自动选图并刷新。

## 8. 会话与继电器流程

首版先实现 `relay_contract.py` 和 `relay_fake.py`。真实继电器 adapter 要等实物型号、协议、
VID/PID/serial、默认触点和断连行为在 R0–R2 封存后再写。

未来现场会话的正常流程固定为：

```text
SAFE_OFF
  → 身份/温度/电流/物理切断人工门
  → relay ON + 电气验证
  → 固件/计划/帧 hash 验证
  → Primer 唯一刷新
  → 固定 dwell
  → Target 唯一刷新
  → 观察/拍照/保持
  → 正常 relay OFF
  → 人工确认电流与画面
```

正常 Primer/Target 之间不切 J2/继电器。任何 UNKNOWN、串口错误、BUSY 超时、回包不符或证据
落盘失败都锁定为 `FAULT_LATCHED/UNKNOWN_DO_NOT_RETRY`；先尝试硬切 OFF，之后必须人工处理。

## 10. 测试与验收

### 10.1 单元/合成测试

- 色卡：旋转/镜像/缺 patch/错误方向/透视/阴影/反光/通道剪裁/未知参考值；
- 颜色：已知变换回归、ΔE00、LOO 残差和不可逆异常输入；
- 配方：重复 ID、非法 transport code、缺来源 hash、未资格化、温度/profile 不符；
- 计划：16 个蓝色配方恰好一次，A/A′ 完整双射，无遗漏、无静默替换；
- 双帧：尺寸、码域、像素到 recipe 的一一对应、左右 controller stream 和 hash；
- 渲染：同输入位级确定、四种模式各自产物完整、原图和 ICC 来源不丢失；
- 继电器 fake：乱码、半包、超时、断连、退出和 UNKNOWN 都停止且不自动重试；
- 阶段三：G3/G4 未满足时任何 LUT 构建/执行入口都确定性失败。

### 10.2 离线完成门

编码阶段结束不等于真屏可执行。首版离线完成必须同时满足：

1. 定向测试、全套测试、格式检查和编译检查通过；
2. 一套 synthetic 24 色卡照片端到端通过；
3. 16 配方 A/A′ 计划和三帧 preview 可人工审查；
4. 一张风景、一张人物、一张渐变图生成四案 comparison pack；
5. fake session 完整重放且证明确切 0 device/network/COM/relay I/O；
6. 输出文档列出所有 `NOT_MEASURED/NOT_RUN/NOT_QUALIFIED`，不将缺证据写成 PASS。

## 11. 建议实施顺序

用户确认本文后，按下列顺序编码，每一步都可独立评审：

1. **P0 数据合同**：chart spec、capture contract、history recipe、evidence/hash；
2. **P1 色卡校正**：人工四角、patch QC、鲁棒变换、ΔE00 报告、合成测试；
3. **P2 蓝色历史计划**：16 recipe、A/A′ 镜像、Primer/Target/White 与 dry-run；
4. **P3 测量分析**：5 s/60 s/10 min、镜像、重复、保持、恢复和候选分类；
5. **P4 静态照片渲染**：recipe quantizer、双帧、四案 preview 和 immutable bundle；
6. **P5 会话骨架**：relay contract/fake、状态机、故障注入和完全离线演练；
7. **P6 实物 adapter**：继电器到货并完成 R0 后，按准确型号另行实现；
8. **P7 现场 release**：离线产物通过人工评审后另行设计和授权；
9. **P8 阶段三**：逻辑分析仪与 G3/G4 证据齐备前保持硬阻塞。

P0–P5 不需要打开 J2，也不需要逻辑分析仪。P6 不接屏完成 R0–R3。P7 才可能安排真屏；P8
与本轮静态照片首版解耦。

## 12. 待用户确认的默认选择

建议按以下默认值开工：

1. 首版只做 JPEG/PNG；RAW adapter 延后；
2. 色卡首版采用人工四角，不先做自动识别；
3. 色卡参考值必须按实物品牌/型号导入，不内置猜测值；

7. P0–P5 只写离线代码；真实继电器 adapter、现场 runner 和任何真屏动作另行放行；

由此产出已校准调色板。
