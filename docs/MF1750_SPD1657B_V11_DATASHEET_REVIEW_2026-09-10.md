## 2. 对明度问题最有用的发现

| 证据位置 | 文档明确的事实 | 对本项目的含义 |
|---|---|---|
| 第 18、25、28 页，PSR/DTM/CDI | P_mode 选择 2 或 3 bit/pixel；3-bit 模式每字节放两个带填充位的像素；DDX 决定 code 与 Gray 索引正向或反向映射 | Gray 0…7 是文档的输出/波形索引名称，没有承诺它们是中性灰、等间隔 L*，也没有承诺八个稳定明度。当前优先目标仍是彩色同色相明度 |
| 第 26 页，PLL/R30 | FR[2:0] 对应 25/32/43/50/65/75/85/100 Hz | 首次在这份同型号资料中给出明确频率表；全局波形时间尺度可进入离线可行性研究，不能再笼统说 PLL 字段完全未知 |
| 第 20–21 页，PWR/R01 | 电源选择、gate/full-source 档位、低压 source 电平及钳位关系有定义 | 可以解释现有 header 对应的名义设置，不能把芯片寄存器范围当作 MF1750 墨水/FPL 的已验证工作范围 |
| 第 18 页，LUT_EN | 0：复位时加载有效 OTP，PON/DRF 模拟设置随 OTP；1：不自动加载 LUT，PON/DRF 模拟设置随 MCU | runtime 与 factory-OTP 路径需要分别分析；只看 host 写入字节不能保证最终有效模拟设置相同 |
| 第 31 页，PTLW/R83 | 九字节窗口结构和 PMODE 有定义；窗口内、外 gate 都扫描 | 局部窗口不等于窗口外像素没有电场，也不能直接证明 local HOLD |
| 第 19、36 页，FOPT/VC_LUTZ/TIEG 等 | 末帧、VCOM 浮空、VGL 收尾选项有定义；浮空后的下一操作需等待系统完全放电 | 可补强保持/收尾分析；不能用末帧控制或 relay OFF 代替放电实证 |
| 第 26–27 页，TSC/TSE | 内置温度采集、0.5°C 步进、温度源/offset 有定义，采集会拉低 BUSY | 温度不必永远缺失，可先设计受控采集与解码；历史 null 保留，命令不加入当前 J2-OFF 四 GET 诊断 |
| 第 15 页，级联 | slave 振荡器/升压/稳压关闭，时钟和高压来自 master | 不能预设 CS1、CS2 可独立调频或调压；仍分别做光学验收，但全局驱动资源要作为共同变量 |

### 已有 profile 的实际对照

读取 `src/generated/spd1657_legacy_535_reference.inc` 以及封印 P2 generated driver，得到：

| 字段 | active / P1 参考 tuple | commented / P2-C tuple |
|---|---|---|
| runtime PSR | `5F E9` | `5F E9` |
| PWR payload | `0F 00 1E 78 20 1E` | `0F 00 24 78 27 20` |
| PLL payload | `02`，文档名义 43 Hz | `03`，文档名义 50 Hz |
| 名义 VSH_LV | +6.0 V | +6.6 V |
| 名义 VSL_LV | -15.0 V | -15.0 V |
| 名义 VSH_LV2 | +6.2 V | +6.9 V |
| 名义 VSL_LV2 | -6.0 V | -6.2 V |
| 本路径实际 R20 发送长度 | 535 bytes | 535 bytes |
| R21 | 704 bytes，全 FF | 704 bytes，全 FF |

这里的电压和频率是**按文档解释的请求值**，不是测量结果。尤其 PWR 固定位存在下述冲突，不能由此声称电源输出已符合规格。R20 的 799 bytes 是带补齐的本地验证容器；P1/P2 实际发送前 535 bytes，不能把 799 当作本次传输长度。

`5F E9` 可分解为 3-bit pixel、MCU LUT 模式、FOPT=3、VCMZ=0、TS_AUTO=1、TIEG=0、NORG=0、VC_LUTZ=1；PSR 分辨率随后由 TRES 的 `512×600` 覆盖。此解码不补齐 waveform 内部 phase。

当前公共初始化源码写 CDI=`3F`，故 DDX=1、像素 code 正向对应文档 Gray 索引。其 VBD=1 是边框选择；局部路径的 CDI=`FF` 令边框 HIZ，**不等于整个显示区的 code 7 是 HIZ/HOLD/白色**。P2 为全帧路径，不进入该局部 CDI 分支。

由此，P1 与 P2 的变化同时涉及 LUT、多个 source 电压请求和帧率，不能把历史光学差异单独归因于某一个变量。旧 include 内 `kRequestedFrameRateHz=0` 仍保持原封印；本次通过旁路报告补充 43/50 Hz 的文档解释，不改封印产物。

## 3. 尚未补齐的关键内容

完整检查 44 页和第 16–17 页命令表后，未找到：

- R20/R21 的 LUT 写入表、payload 长度、11-byte record 的字段/位序。
- phase duration、repeat、frame-count 与 source/VCOM 电平选择的编码关系。

- 全 FF 是否等于零驱动、HOLD、填充或未使用；任何可证明的 HOLD 像素码。
- MF1750 墨水专用的温区 waveform、DC balance 容限或稳定明度阶梯。

R20、R21、E9、AA、E0、R60 等项目所用扩展命令没有列在这份用户命令表中。第 17 页还说明未列出的命令/参数为保留项。因此本资料不能独立替代既有参考工程、加载库、SPI 与真屏证据，也不能据此扫描或改写保留项。

第 19 和 26 页都引用 Appendix 细节，但本文件没有提供对应的波形/参数附录；第 2 页修订记录也提到历史上把 additional information 移到 appendix。找到同型号 Appendix 或匹配的波形编辑/loader 源码，仍是一个具体的补证方向，不以取得官方支持作为唯一出口。

升压软启动 BTST 的 Phase A/B/C 是电源软启动阶段，不能标成像素波形 RESET/SHAKE/DRIVE。未知像素内部 phase 继续写 `OPAQUE`。

## 4. 新识别的文档与实现差异

这些是**待解释差异**，不是本轮软件修复、现场故障结论或厂商勘误定论。

1. **PWR 固定位**：第 20 页要求首字节 A[5:4]=11，而 active/commented runtime payload 首字节均为 `0F`，两位为 00。同页 POR 又标 `0F`，说明复位值与写入要求需分别对待。原参考工程/loader/既有实验为何使用 `0F`，需结合扩展模式与总线/电源证据核查，不能直接改成 `3F`。
2. **公共初始化 PLL**：`src/epd_driver.cpp` 先写 R30=`08`；第 16 页要求 D3=0，第 26 页只解释 0…7。P2 随后覆盖为 `03`，但这一初始化写入仍不能假装符合表格；factory-OTP 路径还涉及 OTP 重载。不能把 `08 & 07` 强行解释成已知的 25 Hz。
3. **CDI 默认标记矛盾**：第 25 页把 DDX=0 标 default；第 28 页把 DDX=1 标 default，且 POR=`9E` 的 DDX 确为 1。实际分析按显式写入的 DDX；不依赖矛盾默认说明。
4. **参数长度/模式边界**：第 17 页要求完整参数后命令才生效；公共 OTP 初始化只向 PWR 写一个 `3F`，与第 20 页六参数形式不同。它可能涉及 OTP/扩展初始化合同，但这份文档没有解释，不能泛化为六参数标准路径已通过。

上述第 2、4 项也涉及独立 white successor 所引用的公共初始化源码，下一次恢复审查必须纳入；原 white BIN/ELF 的文件封印仍可通过，但这与“新资料下语义相符”是两种判断。历史 P2 COMPLETE 和原照片保持有效，不追溯改写为 FAIL；新增 profile/恢复现场入口仍 HOLD_FOR_EVIDENCE / NO-GO。

## 5. 明度路线应怎样更新

### A. 完整端点与历史配方继续保留

已有 code 1↔7 为 camera-relative 同色相候选；CS1 位置重复性、HOLD、fresh-white 重建和双 controller 匹配尚未闭合。Gray 索引说明没有给它增加资格。白恢复清除该候选仍是正常恢复，不能据此判瞬态。

### B. 新增：完整波形的全局时间尺度研究

R30 的语义可从“缺少同型号说明”升级为“文档已说明的全局帧率”。如果某阶段固定为 N 帧且时钟按此配置生效，阶段时间约为 N/f；43→50 Hz 时每帧名义时间从约 23.26 ms 变为 20 ms。这是**条件推论**，不是对未知 LUT phase 的解析结果，也不保证 L* 单调或色相不变。

此方向优先完成离线作用范围审查：确认最后生效的 PLL 写入、OTP/MCU 模式、master/slave 时钟关系、与既有 PWR/LUT 的配对，以及原始 BUSY 数据是否支持时序变化。不能把 25…100 Hz 全范围作为面板安全扫描范围；不能只因 43 与 50 曾分别出现于两个完整 tuple，就批准把它们互换。

在这一步明确前，不生成修改 PLL 的现场固件。将来若能建立单变量有界实验，必须固定完整 LUT、电压、source/target、温度和相机设置，以独立起始态分别比较 CS1/CS2 四位置副本；先筛出 3 个明度等级，再讨论 5/10。**3→5→10 是等级数量，不是刷新重复次数，也不是 PLL 编码数量。**

### C. 电压与收尾控制分别研究

PWR/VDCS 的文档有助于解释电场配置，但还不能成为明度旋钮；VCOM 改动会改变驱动偏置。FOPT/VC_LUTZ/TIEG 属于全局收尾/放电状态分析，不能取代像素内的构色 waveform 或局部 HOLD。

温度遥测可以作为独立离线设计项：保留 raw 两字节和符号/步进解码，绑定采集时间、controller、boot 与 BUSY；必须先检查当前固件是否提供无显示刷新、但会触发采集的受控接口。不能把主动 TSC 命令伪装成无动作 HTTP GET，也不能补造旧实验温度。
