## 0. 决策一句话

本面板的 OTP LUT 实测不是 stock Spectra-6（绿不可寻址，只有 5 色）；**L535（R20 加载）
路径是唯一观测到绿色、且 8 码全部可寻址的路径**，且已有亮光门（≥0.85）下的有效标定数据
（PAL1 亮光批）。因此全彩路线基于 L535 路径构建：实测调色板 → 空间抖动 → 全彩 demo。

## 2. 证据 A：OTP LUT 实测非 stock（排除"OTP 直接全彩"）

PAL2 用**生产固件路径**（`POST /api/frame`，`src/main.cpp:1370` → `src/epd_driver.cpp`，
init 无 0x20/LUT 加载，4bpp nibble 直写 DTM）上屏 8 码列标定帧，亮光批提取：

| nibble | 实测呈色 | 备注 |
|--------|----------|------|
| 0 | 黑（蓝灰偏弱，L*≈40） | |
| 1 | 蓝（浓紫罗兰，C*≈66） | stock 语义应为白 |
| 2 | 白（L*≈73） | stock 语义应为黄 |
| 3 | 红（hue≈5°） | 与 stock 一致 |
| 4 | 黄（hue≈114°） | stock 语义此处无定义 |
| 5 | 白 | |
| 6 | 暗（藏青近黑） | stock 语义应为绿 |
| 7 | 白 | |

等位置换 σ=[0,5,1,3,2,1,0,1]。**绿完全不可寻址**。两批独立复现；空间 identity 三重确证
（几何残差 0.45 vs 备选 ≥37、封印映射、上传 DTM 哈希）+ 帧字节逐列复核，排除
nibble swap / 空间置换 / 帧错误。诊断封印
`.test-output/offline/PAL2_CAL_ANALYSIS_20260925_V1/bright-diagnosis-v2.json`。

含义：OTP 路径在本面板最多 5 色（黑/白/黄/红/蓝），无法全彩。本面板 OTP 疑为定制
测试表（E1002 样例表对不上），是否核实厂商留作开放问题（见 §6）。

如实记录的中间翻转：PAL2 v1 曾被误判"OTP 未覆盖 L535 鬼影"；白清底重刷 v2 与 v1
逐列 ΔE00≤3.2，否决该假设——OTP 渲染是确定性的。另：2026-08-04"OTP 正确六色"的
历史人工观察与本次两批硬测量冲突，以本次为准。

## 3. 证据 B：L535 路径 8 码全可寻址（全彩唯一载体）

PAL1 V5 链（campaign 固件每次刷新向 R20 写 L535 表，
`ec5_lightness_hold_function_chain_v1_driver.inc:308-314`，表源自厂商 REG-API
EDP_init.c）亮光批（照明 ratio 1.076，过 0.85 硬门；10 帧，双侧 ΔE00≤2.31）：

| 码 | 实测呈色（L\*） | 角色 |
|----|----------------|------|
| 0 | 蓝灰 30 | 暗灰/蓝灰 |
| 1 | 浓品红，C\*≈70 | 高色度品红 |
| 2 | 绿 50 | **绿色族** |
| 3 | 暗紫 16 | 深彩 |
| 4 | 黄绿 58.5 | 亮彩 |
| 5 | 暗紫 17 | 深彩 |
| 6 | 绿黄 53 | 亮彩 |
| 7 | 白 65.5 | 白 |

8 码覆盖白、绿族（2 个）、黄绿、品红、蓝灰、两个深彩——明度跨度 L*16~65.5，
色度最高 C*70。**这是本面板上唯一观测到绿色的路径**，且码数（8）多于 OTP 可用色数（5），
空间抖动可组合的明度/色调层级显著更丰富。

数据质量：7 格均匀性失败已归因——6 格 ROI 边缘污染（内缩探针单调下降实锤）+1 格
格内微特征但 Lab 为列典型值；palette build 已加文档化列级稳健规则。

## 4. 证据 C：剂量轴证伪（排除"剂量叠加出多级明度"）

LH3 剂量 V2 链三段 PASS（SOURCE active 白 → DOSE1 commented 8 码列 → DOSE2 同帧
逐字节再施加），16 列判决：**SATURATED=0、DEEPENED=0、HUE_DRIFT=3（码 0 双侧、
码 2 CS2 侧，Δh 5.5°–11°）、INCONCLUSIVE=13**。同码二次施加无一列满足"同色相加深
过门"；码 0/2 呈 XOR-3 类色相漂移。白参照列揭示 ~3 L* 批间系统性偏移（暗会话），
小幅变深不可归因于剂量。

含义：**颜色与明度不是同一个参数轴上的连续量**——不能靠"基础色+剂量叠加"找连续明度。
多级明度只能走行业主干路线：实测调色板 + 空间抖动（证据 D）。

## 5. 证据 D+E：行业路线与受控对照

- 行业对 E6 的"全彩"只有空间抖动一条部署路线（面板厂商配套工具同路线）；ACeP 的
  粒子分层停驻是厂商内部驱动能力，不开放为通用接口，且 ACeP 是 4 颜料不同面板，
  机制不可移植到 E6。详见调研文档 §1–§3。
- PAL1 帧与 PAL2 帧的 6 个码列**逐字节相同**（码 4/7 列生产校验拒收故 PAL2 填白），
  两批上屏结果差异完全由 LUT（L535 vs OTP）造成——这是"L535 与 OTP 呈色互斥、
  且差异源于 LUT 而非帧/空间/流程"的受控实验证明。

3. **L535 全彩路线（选定）**：唯一有绿、8 码可寻址、已有合规标定数据。

开放问题：
- 本面板 OTP 是否为定制测试表（待厂商核实，不阻塞）。
- L535 表的温度依赖与批次一致性未标定（当前数据为单次亮光 session）。
- L535 路径进入生产帧路径需要新固件变体（R20 加载 + 任意帧接收），需新增安全/验收闸
  （设计文档待写）；campaign 固件运维铁律（刷写后首次启动=campaign boot，之后任何
  MCU 复位永久砖命名空间）同样适用。
