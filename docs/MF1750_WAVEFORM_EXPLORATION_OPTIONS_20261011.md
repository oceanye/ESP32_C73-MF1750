# MF1750 / SPD1657 无抖动波形挖掘方案集

日期：2026-10-11
基线：GitHub `df813b5`；本地已有直接波形 handoff 提交 `ffd167e`
目标：通过控制器波形直接激活稳定的颜色/明度中间态，不使用空间抖动、时间抖动或同码重复刷新。

## 1. 先明确研究问题

当前不是继续寻找“另一个颜色码”，而是要判断下面四类机制中哪一类仍可被控制：

1. **时间尺度**：同一组脉冲的帧间隔或总持续时间改变后，粒子停在不同位置；
2. **电压幅度**：VSH/VSL/VSH_LV2/VSL_LV2 改变阈值和迁移距离；
3. **波形结构**：R20 的 category、record 顺序、phase/repeat/HOLD 等字段改变；
4. **历史依赖**：同一目标码在不同历史态、预处理脉冲或中间零场后得到不同最终态。

不要把“某张照片颜色不同”直接判为新色。新中间态必须是：整条区域均匀、与全部端点有明确色差、0/30/60/300 秒保持，并在第二次独立刷新中复现。

## 2. 已知事实和已排除路线

### 已知事实

- L535 路径已经可以稳定写入 535B R20 表，并显示 8 个可寻址代码；8 个代码不等于 8 个已经完成跨控制器校准的独立端点，code 2/5 保留为已观测但尚未完成统一光学校准的候选；
- MAP-v2 的 8×8 有向转换已完成，几何重判后没有确认新的独立稳定颜色；
- 6600↔7200mV 的 VSH 阶梯没有可见移动；
- 6000mV 阶梯因白清污染作废，仍需一次干净补测；
- 当前表结构为 7B header + 6 组 × 8 条 × 11B record；record 字段语义尚未确认；
- `SI0/SDA` 是可能的共享双向线，不能假设存在专用 MISO；
- 当前 L535 初始化与厂商样例在 PSR、PWR、CDI、VDCS、E9/20/21 顺序上不完全相同；
- 当前 runtime 顺序是 `PSR(0x00) → PWR → PLL → TRES → 每颗 CS 的 E9 → R20(535B) → R21(704B FF)`；公共初始化中的 PLL 写入与 runtime LUT 的 PLL 写入必须分开记录；
- 当前格式注册表只覆盖 `E9→R20(535B)`，实际驱动还发送 `R21(704B FF)`；抓包和 manifest 必须把注册合同与实际 driver 序列分别记录；
- 6600/7200 已经证明“只改 VSH_LV”价值很低，但其他电气轴和时间轴尚未系统审查；
- `l535_table_builder.py` 只改变 R20 的 7B header，不会自动同步独立的 PWR/PLL payload，不能直接把 builder 输出当成可上屏固件；
- record 语义审计当前不能在本 checkout 完整复跑：封存脚本要求的旧 `EDP_init.c` 尺寸/SHA 与跟踪文件不一致；现有 record 结论应标记为旧 corpus 证据，不能升级为新字段语义。

### 不再重复

- MAP-v2 全矩阵扫描；
- identical-repeat、同码剂量和全屏重复刷新；
- 6600/7200 的同一 VSH 阶梯；
- 未知字节 0～255 盲扫；
- OTP 写入、擦除和未知命令写入；
- 任何空间/时间抖动方案。

## 3. 推荐总顺序

推荐顺序不是按“最容易看到颜色”排列，而是按信息价值与风险排列：

```text
P0 硬件链路确认
  ↓
方案 A：PLL 时间尺度
  ↓
方案 B：其他 PWR 电气轴
  ↓
方案 C：厂商 profile/category 替换
  ↓
方案 D：单 record / 单位置结构扰动
  ↓
方案 E：历史预处理与中间零场
  ↓
方案 F：被动时序捕获与 SI0/SDA 读回
  ↓
方案 G：高速时间响应测量与稳定态判定
```

如果某一方案出现可解释信号，先做该方案的独立复验，再进入下一方案；不要并行修改多个轴。

## 4. 方案 A：PLL 时间尺度实验

### 4.1 科学问题

保持 R20 表体、PWR、帧和初始化命令不变，只改变最后生效的 PLL code，判断波形的帧时间尺度是否影响粒子最终位置。这里的“改变 PLL”必须同时改变 R20[6] 和 runtime 的 `0x30` payload；只改变 R20[6] 不是有效 PLL 实验。

这里测试的是**时间尺度**，不是“刷新频率越高颜色越亮”的假设。改变 PLL 可能只改变刷新速度，也可能使某些粒子在截止时停在不同位置；两种结果必须区分。

### 4.2 候选

第一轮只做低风险、已有资料解释的相邻档。A1 必须从 active 表和 active PWR 派生，只替换 PLL，不得直接切整套 commented 表，因为 commented 还同时改变其他 header 和 389/535 个 record 字节：

| 变体 | PLL code | 当前解释 | 其他项 |
|---|---:|---:|---|
| A0 | `0x02` | 约 43Hz，现 active 基线 | 全部固定 |
| A1 | `0x03` | 约 50Hz，现 commented header 已出现 | 只改 R20[6] 与 runtime `0x30[0]` |
| A2 | 资料允许且离线审计通过时再选 | 约 32 或 65Hz 的一个相邻档 | 全部固定 |

不要第一轮直接跑 25～100Hz 全范围。高低极端档只在 A1 出现稳定方向后再安排。

### 4.3 现场批次

每个变体：

1. 生产白清 1 刷；
2. 同一 8 条全宽条纹帧 1 刷；
3. 拍摄 `t=0、30、60、300s`；
4. 若发现 ΔE00 或 ΔL* 超过门槛，再独立重复一次。

最低预算：A0 + A1 共 4 刷；复验最多 8 刷。

### 4.4 结果解释

- 只有刷新耗时变化，Lab 不变：`TIME_NO_OPTICAL_EFFECT`；
- 所有颜色整体变亮/变暗：`GLOBAL_TIME_REMAP`，不是新色；
- 个别颜色族出现稳定的新轨迹：进入 A1 复验；
- 只在前几秒出现差异，300s 回端点：`TRANSIENT_ONLY`。

### 4.5 实现要求

新增 PLL 变体只能改变 R20[6] 和最后生效的 `0x30` payload。现有 VSH 阶梯保持 active PLL=0x02 是其单轴设计的一部分；新建 PLL A/B 时不得复用这个固定 payload，必须显式接入所选 PLL 并先通过 R20[6]==PLL[0] 审计，再允许上屏。manifest 必须记录：

- R30/PLL 的写入次数和最后一次值；
- active 表 hash、PWR hash、R20 hash、frame hash；
- 预期帧率解释和实际 DRF 时长。

当前驱动串口尚未输出这些 payload/hash 字段；在现场补齐前，写入次数和最后值必须由被动逻辑捕获确认，离线 hash 由生成包封存，不能把串口启动日志当成完整波形证据。

现有 offline contract 的 `electrical.vsh_mv/vsl_mv` 只容纳一组电压，builder 当前映射到 LV2，不能代表完整 PWR 的 LV/LV2 四路请求值；A/B manifest 必须另列四路请求值并注明 source LV2，不能把该摘要当作完整电气证明。注册表中的 loader hash 还来自旧封存 source corpus，当前跟踪的 `EDP_init.c` 尺寸/SHA 不同，必须同时记录两者身份。

## 5. 方案 B：PWR 联动的电气轴实验

### 5.1 科学问题

6600/7200 的 VSH_LV 无效，不代表 VSH_LV2、VSL_LV2 或较小的 source 电平变化无效。该方案只测试一条电气轴，且必须同时修改 R20 header 和 PWR payload。

### 5.2 候选优先级

先选择与已存在 profile 接近、且不越过手册编码范围的候选：

| 轴 | 基线 | 第一轮候选 | 备注 |
|---|---:|---:|---|
| VSH_LV2 | +6.2V | +6.9V（commented header 中出现，未单轴验证）；+6.5V 为新未证候选 | 先做正向 source 档 |
| VSL_LV2 | -6.0V | -6.2V（commented header 中出现，未单轴验证）；-6.6V 为新未证候选 | 注意负向电压和清除时间 |
| VSL_LV | -15.0V | 暂缓 | 全局影响大，风险高 |
| gate | 20V | 暂缓 | 不能与 source 轴混试 |

VSH_LV 已有 6600/7200 结果，第一轮不重复。

### 5.3 必须成对生成

每个候选必须同时生成：

- R20 header 对应字节；
- PWR payload 对应字节；
- CS1/CS2 完全相同的 payload hash；
- 独立 firmware tag、回退固件 hash；
- 与 active 表体逐字节比较报告。

离线审计还必须断言 `R20[1:5] == PWR[2:6]` 的镜像关系；PLL 候选还要断言 `R20[6] == PLL[0]`。当前生成器尚未自动完成这两类独立 payload 的联动，必须由专用生成步骤完成。

只改 header 的实验只能标记 `HEADER_EFFECT`，不得称为电压实验。

### 5.4 现场预算和停止条件

每个候选 2 刷（白清 + 条纹），第一轮最多 4 个候选、8 刷。出现以下任一项立即停该轴：

- DRF 时间超过历史基线 1.5 倍；
- 白清后背景未恢复白；
- 出现大面积藏青残留、局部永久不响应或 BUSY 异常；
- 两颗控制器出现明显不同步。

### 5.5 结果价值

该方案即使没有新色，也能回答“电源幅度是不是主要瓶颈”。如果出现只对某一颜色族生效的单调轨迹，再进入同一轴的窄间隔搜索；不要立刻扩大到二维电压网格。

## 6. 方案 C：厂商 profile / category 替换

### 6.1 科学问题

仓库已经有 `WF20_25`、`WF23_25` 的经验 profile，以及当前 MF1750 L535 表。它们不是当前 535B 六 category 的同几何表：WF20/WF23 是 9×8×11 的跨工程 opaque body，颜色 category 映射和 mode-1 loader 仍未证实。该方案只能回答“差异结构是否提供因果线索”，不能把跨 profile 数据直接拼入当前 535B。

### 6.2 category 坐标

下面的 88B 区域只表示 legacy 535 源码中的结构切片，不表示 WF20/WF23 的颜色语义：

| 区间 | 现有标签 | 第一轮建议 |
|---|---|---|
| `[7:95]` | VCOM | 高风险，后置 |
| `[95:183]` | Black | 可选 |
| `[183:271]` | White | 优先 |
| `[271:359]` | Yellow | 优先 |
| `[359:447]` | Red | 第二轮 |
| `[447:535]` | Power | 高风险，后置 |

第一轮只允许在 legacy active/commented 的 535B 同几何表内部做离线差分；若要使用 WF20/WF23，只能先做离线差异聚类，不得把其 record 直接嵌入 535B。若后续具备同代 loader 和牺牲屏，才可另立 `C-mode1` 批次。legacy 内部候选可按以下方式构造：

1. 保留 MF1750 active header；
2. 只替换一个 88B category；
3. 其他 5 个 category 保持当前表体；
4. 首选 White 或 Yellow 其中一个；
5. 只在离线结构审计通过后生成真屏候选。

### 6.3 两级测试

- **C0 离线级**：检查长度、header、category 边界、record 数量、全 FF 记录和差异聚类；不接设备。
- **C1 牺牲屏级（当前 NO-GO）**：只有取得同代 loader/ABI 证据、明确牺牲屏授权和可回退固件后，才允许一个 category 一个批次，白清 + 条纹各 1 刷；当前不能把 commented 表或 category splice 直接生成现场固件。

若未来 C1 使所有码整体塌缩、出现严重残留或几何异常，立即停止该 profile，不再移植其他 category。

### 6.4 重要限制

`WF20_25/WF23_25` 是跨工程经验资料，不是当前 MF1750 的厂家授权波形；已有真屏 profile 结果也没有产生新的独立稳定色。不能把“解密成功、长度相同”解释成“可以安全使用”。禁止把 799B H3 body 或 WF20/WF23 record 直接嵌入当前 535B；任何 vendor tuple 真屏实验都必须另用牺牲屏、独立 loader、独立回退路径，且禁止写 OTP。

## 7. 方案 D：单 record / 单位置结构扰动

### 7.1 科学问题

如果 legacy 535B category 级差分显示出方向性信号，再进一步寻找 11B record 中哪些位置与颜色/亮度有关。但 record 字段尚未有语义，因此只能做**有边界的差分实验**。

### 7.2 选择规则

只有在 legacy category 级差分已经出现方向性信号后，才从 active/commented 两张同几何 535B 表中挑选。WF20/WF23 不得作为 535B record 的直接候选来源：

- 同一 category 内、同一 record 位置；
- 只在两个已知 legacy 535B profile 之间出现的差异；
- 相邻候选之间只差 1～2 个 byte；
- 不选择跨 category、跨 header、跨 PWR 的混合位置。

一次只改一个 record，或同一 record 内一个 byte。不得直接把 byte 命名为 phase、repeat 或 HOLD；在没有厂商证据前统一称为 `record_offset_N`。

### 7.3 建议批次

先做 3 个候选：

| 候选 | 变量 | 目的 |
|---|---|---|
| D1 | White category 的一个 record | 看白到彩的迁移是否变化 |
| D2 | Yellow category 的一个 record | 看高亮彩色族是否变化 |
| D3 | 同一 category 的相邻 record | 看是否存在位置/phase 规律 |

每候选 2 刷，出现信号后再复验 2 刷。最低 6 刷，最多 12 刷。

### 7.4 允许的结论

- 单码或单色族稳定变化：`RECORD_CANDIDATE`，进入窄范围邻近值测试；
- 所有码都整体变化：可能是全局时序/电气影响，降级为 `GLOBAL_REMAP`；
- 几何错位、旋转、残留：`MECHANISM_ANOMALY`，不用于色彩结论；
- 只在一个刷新瞬间出现：`TRANSIENT_ONLY`。

## 8. 方案 E：历史预处理与中间零场

### 8.1 与 MAP-v2 的区别

MAP-v2 测试了大量 history→target 组合，但没有单独分离“预处理脉冲”“零场等待”和“最终目标波形”。本方案不再做 8×8 全矩阵，而是固定一个目标码，研究目标前的历史处理。

### 8.2 三种低维链

| 链 | 历史处理 | 目标 |
|---|---|---|
| E1 | 白 → 目标 | 基线 |
| E2 | 黑 → 目标 | 强历史对照 |
| E3 | 白 → 零场/保持 → 目标 | 判断中间零场是否解除历史依赖 |
| E4 | 彩色端点 → 零场/保持 → 目标 | 判断彩色残留是否能被消除 |

每条链只选一个目标颜色和一个目标码，避免重新扫描全矩阵。零场的实现必须绑定到同 profile、已验证的控制器路径；当前公开资料和现有审计尚未证明通用 HOLD 电平，因此 E 方案暂列离线/后置，不得凭空添加未知命令。

这不是重新做 MAP-v2。历史路线已经出现过一次性明度候选，但 HOLD/保持电平没有电气证据；本方案只复核 fresh-white、零场/保持变量和长期稳定性，不重复同码剂量或 8×8 全矩阵。

### 8.3 采样

同一目标在 `t=0、5、15、30、60、300s` 采样。E3/E4 如出现明显差异，才增加 900s 点判断是否只是慢速回退。

### 8.4 判定

- 历史不同但 300s 同一端点：`HISTORY_TRANSIENT`；
- 历史不同且 300s 稳定、二次复现：进入 `NEW_INTERMEDIATE` 复验；
- 只有几何/残留变化：`MECHANISM_ANOMALY`。

## 9. 方案 F：被动时序捕获与 SI0/SDA 读回

### 9.1 目的

该方案不直接寻找颜色，而是补齐最关键的机制证据：真实运行中 E9、20、21、R20、R21 的长度、间隔、CS 对象和 GPIO 方向。

仓库已有 `tools/mf1750_spd1657_spi_capture_audit.py` 的抓包审计入口，优先沿用它的 JSON、原始逻辑文件 hash 和命令重建格式，不重新发明现场记录格式。

### 9.2 逻辑分析仪通道

优先捕获：

`CS1、CS2、SCK、SI0/SDA、DC、BUSY、RST、可用的电源/高压监测点`

先对生产基线或已经验证安全的 L535 变体做一次被动捕获。若需要读取 `0x70`，先确认 SI0/SDA 三态切换、串联电阻和 GPIO11 方向；读回异常时立即停止，不把随机字节解释成寄存器真值。

### 9.3 输出

- 每条命令的开始/结束时间；
- CS1/CS2 的发送对象；
- R20/R21 实际发送长度；
- E9/20/21 前后的等待和 DRF 时序；
- 读回时 GPIO 方向切换证据。

这些信息可以决定下一步是继续改表体，还是先修正 loader/控制器状态问题。

## 10. 方案 G：时间响应测量

### 10.1 目的

已有照片主要在 0/30/60/300s 取样，可能错过短暂但可重复的中间态。该方案只增加测量密度，不增加新的颜色算法。

### 10.2 推荐采样

对一个已知安全条纹帧：

`0、1、2、5、10、15、30、60、120、300、900s`

使用固定曝光、固定白平衡、固定 ROI 和同一台架。优先用相机；若要更高时间分辨率，可加光电二极管或光敏传感器，但必须先做不接触面板的基线校准。

### 10.3 结论分层

- 只有 1～5s 的短峰：机制线索，不是可用稳定色；
- 30～300s 稳定、900s 不回退：可进入波形保持研究；
- 多次曲线形状一致但终点相同：记录为动态响应，不计新明度级。

## 11. 建议的第一轮实际安排

如果用户准备安排一轮现场调试，建议按 6 刷上限执行以下三项；这是 conditional 排程，不代表当前已有可上机固件。C0 的 active 基线可作为 A0，避免重复刷新；A1/B1 必须先生成专用 bundle、编译、做 hash/镜像审计和被动捕获闭环后，才获得上机资格：

### 第一项：P0 + 被动捕获

- 0 刷新；
- 确认 J2、BUSY、照明、台架和设备身份；
- 捕获一次生产/L535 基线时序。

### 第一项补充：C0 active 基线

- 白清 1 刷，确认白场和 DRF；
- 同一全宽 8 条纹 1 刷，拍摄 0/30/60/300s；
- 这 2 刷同时作为 A0 参考，不再单独重复 A0。

### 第二项：A1 PLL 对照

- 2 刷起步；C0 active 基线可作为 A0，有信号后再独立复验 2 刷；
- 只改变 PLL code `0x02 → 0x03`，同时修改 R20[6] 与 runtime `0x30[0]`；
- 使用同一全宽 8 条纹；
- 采样 0/30/60/300s。

### 第三项：B 轴单变量

- 首选 VSH_LV2 +6.9V，VSL_LV2 -6.2V 作为第二候选；两者都只在 commented tuple 中出现、没有独立单轴证据，+6.5V/-6.6V 标记为新未证插值，不作为第一候选；
- B 变体保持 runtime PLL=0x02、R21=704B 全 FF；R20[1:5] 与 PWR[2:6] 必须成对变化，不能只改表头；
- 2 刷起步，白清污染或 DRF 异常立即停；
- 若有方向性信号，再安排另一个候选。

这三项可以回答：颜色差异究竟更接近“时间尺度”“电气幅度”还是“隐藏装载/记录结构”。

## 13. 统一判定标签

| 标签 | 定义 |
|---|---|
| `NEW_INTERMEDIATE` | 新的、均匀、稳定、可复现的直接波形态 |
| `NO_CHANGE` | 与基线差异落在噪声门内 |
| `ENDPOINT_REMAP` | 只是已有端点或已有码别名 |
| `GLOBAL_REMAP` | 所有颜色一起亮/暗/偏移 |
| `HUE_DRIFT` | 色相改变但没有形成新稳定色阶 |
| `TRANSIENT_ONLY` | 只在短时间窗口出现 |
| `UNSTABLE` | 随时间衰减或二次刷新不复现 |
| `MECHANISM_ANOMALY` | 几何、残留、总线或控制器状态异常 |
| `SAFETY_ABORT` | BUSY、DRF、供电、照明或刷写门失败 |

## 14. 不能做的事

- 不同时改变 PLL、PWR、VCOM、gate、record；
- 不把 799B 本地容器直接当成当前 535B 发送合同；
- 不把跨工程 WF20/WF23 资料直接当作当前面板授权波形；
- 不在没有 SI0/SDA 三态证据时接入读回驱动；
- 不以一张照片或一条短暂亮度变化宣布新颜色；
- 不为“看起来可能有效”而突破刷新预算；
- 不改变生产驱动封印文件；
- 不执行 OTP 写入、擦除或未知命令写入。

## 15. 最终建议

当前真正可推进的三条路线是：

1. **PLL 43↔50Hz**：成本最低，能检验全局时间尺度；
2. **VSH_LV2 或 VSL_LV2 单轴**：能检验除 VSH_LV 之外的电气阈值；
3. **legacy active/commented 的离线 category 差分**：先定位颜色族结构差异，不把结果直接当作可上屏波形。

只有前两条出现可解释信号后，才值得申请受控的 category/record 真屏实验。若前两条均为 `NO_CHANGE`，下一步重点应转向方案 F 的被动时序捕获、同型号 Appendix/loader 获取和已有 C20/T20 完整 profile 对照，而不是继续盲目扩大扫描范围。
