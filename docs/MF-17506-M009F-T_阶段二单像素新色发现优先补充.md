# MF-17506-M009F-T 阶段二单像素新色发现优先补充

状态：`DISCOVERY-FIRST / OFFLINE IMPLEMENTATION IN PROGRESS / NOT LIVE-AUTHORIZED`  
生效日期：`2026-08-21`  
上位计划：[`MF-17506-M009F-T_阶段二与阶段三测试计划.md`](MF-17506-M009F-T_阶段二与阶段三测试计划.md)

## 1. 操作者目标与优先级

当前阶段二首先寻找**可由单个像素自身的时间历史控制得到的额外颜色状态**。60 s、10 min、
重复性和长期保持测试后移，只对即时筛查命中的候选补做。

本补充不降低最终资格化标准。即时命中只能记为 `DISCOVERY_HIT`，不能提前命名为稳定新色、
生产调色板颜色或新颜料色。

## 2. 明确排除

- 不使用 Bayer、棋盘格、误差扩散、蓝噪声、DBS、Atkinson 或任意空间抖动；
- 不用相邻不同颜色像素在观看距离上融合成“新颜色”；
- 不把相机虚焦、网点、残影、边界污染或左右控制器差异记为单像素新色；
- 阶段二仍只调用 factory OTP，不写 runtime LUT，不中断刷新，不假定局部刷新已可用。

已有 dither atlas 的橙、紫、棕、粉红、青绿等外观只保留为空间混色证据，不进入本路线的
单像素候选表。

## 3. 单像素颜色状态的实验定义

发现阶段使用大色块，但色块内部每一个像素必须经历完全相同的 `source→mid→target` 编码历史。
大色块只是把许多同态单像素并列以便肉眼和相机观察，不允许在色块内混排不同 transport code。

命中定义包括两类：

1. 与七个已知状态明显不同的色相；
2. 同色相下可重复区分的明度或饱和度状态。

任何命中之后，必须用微距照片确认色块内部像素同态，再用 1 px、2 px、4 px、8 px 同配方区域
验证该状态可以在像素尺度独立编码；该桥接测试也不得依靠空间混色。

## 4. 已有筛查结论

- 较早两步 8×8 matrix 是先导证据：target code 4/7 曾出现历史相关蓝色明暗变化，但尚未完成
  单像素资格化；
- 已完成的 chroma-history campaign 覆盖
  `source 0..7 → mid 4/7 → target 2/3/5/6`，共 64 条语义序列/控制器；
- 该 campaign 的 target 只见 `黄红蓝绿黄红蓝绿`，各 source 行无差异，没有发现新的最终
  单像素颜色；mid 阶段个别行明暗差异带有操作者“不一定准确”的限定，保留为弱候选证据。

## 5. 局部刷新能力裁决

当前只能确认本机驱动支持双控制器完整 DTM 上传和全局 `PON→DRF→POF`。精确面板规格把命令
定义转交给未取得的 SPD1657B rev `0x04` command datasheet；现有本机资料没有 window 坐标、
old-frame RAM/格式、partial waveform、边界规则或 cleanup 次数。

相邻 800×480 Spectra 6 样例的 `0x86` helper 被源码明确标为暂不使用、为未来 dither image
保留且依赖 dithering area。它既不是局刷命令，也不是 MF-17506 的精确支持包。E Ink 平台级
Sparkle partial-image 宣传同样不能证明当前 MF-17506 + 双 SPD1657B + 当前 OTP 支持该功能。

因此当前裁决为：

- `TRUE_PARTIAL_REFRESH_SUPPORTED = UNKNOWN`；
- `CURRENT_DRIVER_PARTIAL_REFRESH_AVAILABLE = FALSE`；
- `GUESSED_PARTIAL_COMMAND_HARD_BLOCKED = TRUE`；
- 在取得精确 command/support package 前，不做发送未知命令的真屏“探测”。

只改变全帧中的一个 ROI、随后执行全局 DRF，只能称为 `ROI_DATA_CHANGE_UNDER_GLOBAL_REFRESH`；
即使其他区域肉眼不变，也不能证明它们没有被全局波形重新驱动，不能冒充局部刷新。

## 6. 无需局刷的全量 512 序列发现批次 D1-512

局部刷新不是提高本轮样例数的必要条件。DTM 本身允许每个像素在同一次全局刷新中使用不同
transport code，因此可以把大量**时间历史不同、空间内部同态**的 ROI 并行放入同一组帧。

D1-512 取代先前的 128-recipe D1 草案作为首选：

- 枚举 `source 0..7 × mid 0..7 × target 0..7 = 512` 条三步历史；
- 使用每半屏 `11列 × 24行 = 264` 个位置，两半合计 `22×24=528` 个 ROI，没有 ROI 跨越中心边界；
- 每个 ROI 为 `40×22 px`，横向 4 px、纵向 2 px 白缝；每半屏 `x0=16`，全屏 `y0=13`，内部所有像素使用同一 code；
- 512 格放完整三步历史；每个控制器另放 code 0–7 共 8 格参考，左右合计 16 个参考格；
- CS1/CS2 承载不同 recipe bank，不在发现轮浪费一半面积做镜像；任何命中再单独左右互换；
- 生成无文字的真屏帧、带 `(source,mid,target)` 标签的离线 preview、ROI CSV/JSON 和照片分析模板。

固定可见动作仍然只有：

1. standard white baseline；
2. 512-recipe source frame；
3. 512-recipe mid frame；
4. 512-recipe target frame；
5. standard white recovery。

这五次都是全屏全局刷新，但一次完成全部 512 条单像素历史筛查。target 完成后立即拍全屏和左右
近照；只标记与同 target code 参考状态相比存在色相、明度或饱和度差异的 ROI。没有空间抖动，
也不利用观看距离融合颜色。

### 6.1 先前 128-recipe D1 草案

先前计划的左右 bank `mid2/3` 与 `mid5/6` 进入 target `0/1/4/7`，是 512 全量中的优先子集。
它保留为 D1-512 无法达到 ROI 可辨识度时的降级版，不再是默认首选。

## 7. 原 128-recipe D1 降级布局

保持现有 1024×600、左右各 8×8、4 px 白缝布局。每个 ROI 内部为单一 transport code，左右
控制器改作两个不同的候选 bank，以一次 target 画面筛查 128 条互不重复的三步历史；命中项再
做左右位置互换确认。

每行的 `source` 依次为 code 0–7。八列的 `(mid→target)` 固定为：

| Bank | 控制器 | 第1–8列 `(mid→target)` |
|---|---|---|
| D1-L | CS1 | `2→0, 2→1, 2→4, 2→7, 3→0, 3→1, 3→4, 3→7` |
| D1-R | CS2 | `5→0, 5→1, 5→4, 5→7, 6→0, 6→1, 6→4, 6→7` |

该批优先搜索黄/红/蓝2/绿历史进入黑、白、Blue-1 和 alias-blue 目标时，是否出现额外的单像素
色相、明度或饱和度状态。code 7 只作 alias 路径控制，不先命名为第八个原生颜色。

固定可见动作仍为：

1. standard white baseline；
2. uniform-per-ROI source；
3. uniform-per-ROI mid；
4. uniform-per-ROI target；
5. standard white recovery。

发现阶段只在 target 刷新完成后的即时观察门记录颜色、明暗、均匀性、白缝和左右异常；不等待
60 s/10 min。每项仍是一动作一决策，无 retry/recovery/autochain，最后必须 clean-white 收尾。

## 8. 命中后的顺序

1. 原位置即时复核照片；
2. 左右控制器和屏幕位置互换，只复测命中 recipe；
3. 1/2/4/8 px 同配方尺度桥接；
4. 通过以上三项后，再补 60 s、10 min、重复 3 次/10 次及长期保持；
5. 通过色卡校正后计算相对 Lab/ΔE，并决定是否进入单像素 `HISTORY-PALETTE`。

如果 D1-512 的照片分辨率或 ROI 均匀性不足，降级到 128-recipe D1，而不是把模糊结果记成
`NO_HIT`。如果 D1-512 质量合格且无命中，记录 `NO_HIT_IN_ALL_8_CUBED_FACTORY_OTP_TRIPLES`；
不得在现场自动切换到未知命令、partial、LUT 或 waveform 探测。
