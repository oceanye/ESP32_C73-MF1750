# MF1750 无抖动直接波形测试交接（2026-10-11）

> 本文供现场测试执行。目标是寻找**由波形直接产生、可重复且稳定的物理中间态**，不使用空间抖动或时间抖动。
> 本文只规定测试顺序和证据要求，不授权自动上电、刷写或刷新。

> **状态更新（2026-10-11 10:45 +0800）：路线选择以 [`MF1750_WAVEFORM_EXPLORATION_OPTIONS_20261011.md`](MF1750_WAVEFORM_EXPLORATION_OPTIONS_20261011.md) 和 `STATUS_HANDOFF.md` 最新条目为准。** 本文原有的 S1 current/vendor-like A/B 和 W1 现场安排已被新方案收紧；在 A1 PLL、B1 PWR 专用 bundle 完成离线审计并获得上机资格前，不执行 vendor-like、category、record 或整套初始化替换。

## 1. 入口和边界

- 仓库基线：`df813b5`（`main`）。
- 当前生产固件：RC2G，最后已知 hash 见 `STATUS_HANDOFF.md` 顶部。
- 用户目标：每种颜色获得 10 级以上明度，且每一级来自波形直接激活。
- 当前已知事实：
  - MAP-v2 64 个有向转换在几何重判后没有新的独立色；
  - 6600↔7200 mV 的 VSH 阶梯没有可见移动；
  - 6000 mV 数据因白清污染作废，尚未形成结论；
  - stock LUT 已测范围内没有找到稳定新端点，但这不等于已经证明控制器所有隐藏 LUT/record 机制都不存在中间态。

因此，**抖动色谱只能作为备用路线**。本交接的主线是：

```text
硬件链路确认 → 初始化序列对照 → LUT/record 机制定位 → 单变量波形实验 → 稳定性复验
```

## 2. 现场前置条件

### 2.1 面板和继电器

1. 面板、FPC、转接板、相机和台架均保持当前位置，禁止在同一批次中移动。
2. 现场确认 J2 的真实接线，不把“J2=继电器 CH2”当作已证事实。
3. 继电器打开、面板上电后，独立查询 `BUSY`；`BUSY=0` 时立即停止，禁止刷新。
4. 长时间断电后的第一次测试，先通电静置约 20 分钟，再做白清或波形刷新。
5. 每次批次结束：恢复生产固件、等待状态稳定、relay OFF，并记录屏上保留的帧。

### 2.2 刷写和版本

- 刷写前：relay OFF、J2-off、核对 bin SHA256、核对 build tag。
- 刷写后：先做版本和网络诊断，再做 `BUSY` 检查；不要把刷写成功等同于面板可刷新。
- 生产 `src/epd_driver.cpp` 不做原地修改；实验变体使用独立 translation unit 和独立 build tag。
- 不使用 campaign 固件，不写 OTP，不探测未知命令的写入副作用。

### 2.3 数据线认知

本板没有已确认的独立 MISO。SPD1657B 的 `SI0/SDA` 可能承担共享双向读回功能，但 GPIO 方向切换和读回时序必须先实证。做“ MISO 转接板”之前，先核对 FPC/转接板引脚和实际电气方向；不要把一个未确认的专用 MISO 当作实验前提。

## 4. P0：零刷新现场确认

记录以下结果后才能进入 S1：

- 生产固件 tag、bin SHA256、设备 IP/MAC、NVS 状态；
- J2 实际接线和继电器通道映射；
- relay OFF/ON 各状态下的 `BUSY`、供电状态和诊断响应；
- 相机型号、分辨率、焦距、曝光、白平衡；
- 照明 ratio，目标窗口为 `[0.85, 1.3]`；
- 当前屏幕照片、台架四边形和时间戳。

P0 不发送白清、不发送 `DRF`、不上传帧。`BUSY=0`、供电状态不确定或台架几何无法复现时，停在 P0。

## 5. S0：冻结两个可审计的初始化序列

离线建立两个 manifest：

- `S0-current-l535`：仓库当前 L535 路径；
- `S0-vendor-like`：依据 `参考资料/REG-API-oqc(1)(1)/REG-API-oqc/User/EDP_init.c` 和相关样例整理的路径。

每个 manifest 至少列出以下字段、参数长度、发送对象、等待条件和顺序：

`reset → AA → PSR → PWR → BTST → POFS → PLL → CDI → TRES → VDCS → E9 → R20 → R21 → DTM → DRF → POF`

重点标出当前路径和样例在 PSR、PWR、CDI、VCOM/VDCS、`E9→20→21` 关系上的差异。S0 只做离线逐字节审计，不进行现场试探。

## 6. S1：序列 A/B 对照

### 6.1 固定项

- 使用同一个 8 条全宽条纹帧，代码 0～7 各一条；禁止抖动、渐变和小方块角标；
- 使用同一 R20 535B 表、同一帧 hash、同一等待时间、同一照明；
- 两颗控制器使用相同 payload，分别记录 CS1/CS2；
- 不同时改变 PWR、PLL、VCOM、gate 或 record。

### 6.2 刷新安排

对每个序列分别执行：

1. 白清 1 刷，拍白场并确认 `DRF` 正常；
2. 条纹帧 1 刷，拍摄 `t=0、30、60、300 s`。

比较目标：序列差异是否造成端点置换、整体色相漂移、清除速度变化或真实的中间态。只要 A/B 不能在同一帧、同一几何和同一照明下解释，就不进入 W1。

## 7. W1：直接波形候选顺序

W1 每个候选单独建批次，每批只改变一个变量，其余命令和数据固定。优先级如下：

### W1-A：已知序列字段

在 S1 发现差异后，才拆分 PSR、CDI、VCOM/VDCS 或 PWR 的具体字段。不能把整套 vendor-like 序列的结果直接归因于某一个字段。

### W1-B：record 的 phase/repeat/HOLD

只有在 active/commented 表差异、厂商资料或逻辑分析仪时序能给出字段语义后，才改变 11-byte record 中的单个字段。未知字节不得做 0～255 盲扫。

### W1-C：R20 表体和 LUT 行

沿用 535B 结构和 6×88B 几何，先选择一行或一个已知 phase 段做单变量副本。必须保留原始表、修改位置、修改前后 hash 和恢复表。

### W1-D：PWR+header coherent

6000/6600/7200 mV 只作为电气对照，不再把 header-only 称为电压实验。电压候选必须同时记录 R20 header、PWR payload、两颗控制器 hash；若只改 header，结果标记为 `HEADER_EFFECT`。

## 8. V0：6000 mV 干净补测

V0 只为补齐现有阶梯证据，不是直接波形主线。进入条件：

- 白清后白场背景保持白，不出现藏青残留；
- `DRF` 时长回到历史基线附近；
- 白场照片和照明门均通过；
- PWR payload 与 R20 header 已成对生成并核 hash。

若白清再次污染或超时，V0 作废并停止，不重复追加刷新。

## 9. 光学判定

一个结果只有同时满足以下条件，才能标记 `NEW_INTERMEDIATE`：

1. 全宽区域均匀，不能是小面积欠驱动、残留或几何错位；
2. 与全部已知端点保持建议 `ΔE00 ≥ 3` 的距离；
3. CS1/CS2 同码差异在既有门槛内，建议 `ΔE00 ≤ 3`；
4. `t=0、30、60、300 s` 的衰减不跨回端点，且第二次独立刷新可复现；
5. 结果不是整体变亮/变暗、色相漂移、码轴置换或转换截断。

统一使用以下判定标签：

| 标签 | 含义 |
|---|---|
| `NEW_INTERMEDIATE` | 新的、稳定、可重复的直接波形中间态 |
| `NO_CHANGE` | 与基线在门槛内无差异 |
| `ENDPOINT_REMAP` | 只是落到已有端点或已有码的别名 |
| `HUE_DRIFT` | 色相改变但没有形成新稳定色阶 |
| `UNSTABLE` | 随时间衰减、重刷不复现或两侧不一致 |
| `MECHANISM_ANOMALY` | 几何、方向、残留或总线机制异常，不能用于颜色结论 |

## 10. 每批必须封存的证据

每个批次目录至少包含：

- `manifest.json`：批次 ID、预算、commit、固件和表 hash；
- `command-sequence.json`：逐命令顺序、参数、等待和 CS 对象；
- `frame.bin` 及其 SHA256；
- `photo-t0.jpg`、`photo-t30.jpg`、`photo-t60.jpg`、`photo-t300.jpg`；
- 原始照片到 Lab 的提取结果和照明 ratio；
- `verdict.json`：上述统一标签、判定理由和未决问题；
- `SHA256SUMS`、中止记录和最终 relay/MCU/屏幕状态。

文件目录使用 O_EXCL，manifest 完成后再计算 canonical hash。现场照片、逻辑分析仪原始文件和中止证据不入 Git，但必须在 handoff 中写出路径和 hash。

## 11. 立即执行入口

用户现场安排测试时，按以下顺序回传结果：

1. P0：J2 映射、BUSY、供电和照明门；
2. S0：两个初始化序列 manifest；
3. S1：A/B 两组 4 张主照片和两个 verdict；
4. 若 S1 有可解释差异，再选择一个 W1 候选；
5. 每完成一个批次，先更新 `STATUS_HANDOFF.md`，再决定下一批。

不要先跑 MAP-v2、不要重复 6600/7200 阶梯、不要同时改多个波形轴。当前最有价值的问题是：**同一 R20 和同一帧，在不同初始化/LUT 装载机制下，是否能稳定钉住一个新的直接物理态。**
