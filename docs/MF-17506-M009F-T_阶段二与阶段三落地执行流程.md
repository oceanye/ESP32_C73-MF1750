### 4.1 继电器统一接口

真实 adapter 至少实现：

```text
discover() -> exact device identity
connect(expected_identity)
command_off()
command_on()
read_commanded_state() -> ON/OFF/UNKNOWN
close()
```

`read_commanded_state()` 只代表控制器回报，不证明驱动板真的有电或已经掉电。R2/R3 必须通过
电压或电流实测标定。软件不得只凭 COM 号选设备，必须同时绑定 VID、PID、USB 序列号和型号；
MCU 与继电器端口必须由不同 identity 区分。

### 4.2 电源状态机

```text
SAFE_OFF
  └─ operator gate + relay identity + electrical setup
       → POWERING_ON → ON_VERIFY → RUN_READY
RUN_READY
  ├─ exact visible action → ACTION_ACTIVE → RUN_READY
  ├─ normal close → POWERING_OFF → OFF_VERIFY → SAFE_OFF
  └─ anomaly → FAULT_LATCHED → emergency OFF → manual inspection
```

- `POWERING_ON` 期间禁止 MCU 刷写和可见刷新。
- `ACTION_ACTIVE` 期间普通软件不得切继电器；只有明确硬件异常允许紧急断电。
- 任一串口超时、回包不符、日志落盘失败或状态为 `UNKNOWN` 都进入 `FAULT_LATCHED`，不自动重试。
- 程序退出时尝试发送 OFF，但若实测继电器在 USB 失联后保持最后状态，就不能把退出清理视为
  硬件 failsafe；在增加 watchdog/eFuse 前禁止无人值守。

## 5. 继电器到位后的验收流程

### R0：身份和文档封存

1. 拍摄继电器正反面、端子标识和铭牌。
2. 保存厂家命令手册或协议文本，不从其他相似板卡猜命令。
3. 只连接 PC，不接触点负载；读取设备管理器/USB 枚举的 VID、PID、serial、COM 和驱动名。
4. 验证插入、拔出和 PC 重启时触点默认状态；用万用表蜂鸣/电阻档确认 COM–NO。
5. 若上电、枚举或打开串口会短暂吸合，R0 直接失败，不接驱动板。

### R1/R2：空载和假负载

1. 运行 OFF 10 次，确认幂等且不会反向变 ON。
2. 运行 `ON→OFF` 100 次，记录命令、回包、接点状态和动作时间。
3. 分别在 ON 和 OFF 时拔 USB、关闭控制进程、让 PC 睡眠/唤醒，记录继电器保持还是释放。
4. 制造串口占用、乱码、半包和超时，fake/真实 adapter 均应 fail closed。
5. 若继电器失联后保持 ON，标记 `NO_HARDWARE_FAILSAFE`；仍可有人监督使用，但不能无人值守。

### R3：驱动板无屏验收

1. 物理切断保持可用；面板不接，MCU SPI 先置安全态。
2. 电源正极通过 `COM→NO` 接驱动板输入；负极和 MCU 共地。继电器不得旁路现有物理切断。
3. 校准 ON 后输入稳定时间、OFF 后输入和 TP1 残压下降时间。
4. MCU USB 保持连接，继电器 OFF 时检查驱动板是否被 SPI/GPIO 反向供电。
5. 如有反向供电，先增加具备部分掉电保护的三态缓冲器；未解决前不得接屏自动循环。

R0–R3 全部通过后，才能生成绑定该继电器 identity 的真实 session release。

## 6. 阶段二的正式执行顺序

### 6.1 七个正式视觉状态

阶段二主矩阵固定使用 transport code `0–6`：

| code | 当前人工颜色名 | 角色 |
|---:|---|---|
| 0 | 黑 | 正式状态 |
| 1 | 白 | 正式状态/恢复参照 |
| 2 | 黄 | 正式状态 |
| 3 | 红 | 正式状态 |
| 4 | Blue-1 | 正式状态 |
| 5 | Blue-2 | 正式状态 |
| 6 | 绿 | 正式状态 |
| 7 | 与 code4 肉眼等色 | alias 控制，不作为第八个新颜色 |

每个正式批次保留至少一个 `code4↔code7` alias 控制格，用于发现控制器或会话漂移。

### 6.2 S2-PRE：完全离线准备

1. 生成 42 个 `Ci→Cj, i≠j`，按 14 项/批分为 A/B/C 三批；每批另留 2 格为白和 alias 控制。
2. 为每批生成左右位置镜像版 A′/B′/C′，pair identity 不变，只改变 ROI。
3. 冻结 source/target/white 三帧及 preview SHA-256；每批最多 3 个可见动作。
4. 为照片预生成 ROI、编号、灰卡区域和文件名，不依赖现场手工命名。
5. 生成 dry-run transcript，fake relay 和 fake MCU 下证明 0 真实 I/O、异常不自动继续。

### 6.3 S2-0：新测试台基线

1. fresh 现场检查并建立 session；继电器处于 OFF，物理切断就绪。
2. 上电、初始化 factory OTP，执行全白健康检查。
3. 执行三轮 `7色条→观察/拍照→标准白恢复`，总计 6 个可见动作；正常轮次之间不切继电器。
4. 每轮记录 BUSY、输入电流、温度、左右一致性和白恢复。
5. 三轮任一异常即停止；不得为了凑足三轮自动重放失败动作。

S2-0 通过只证明新测试台基线稳定，不自动授权 S2-1。

### 6.4 S2-1：42 个两步转换正式确认

每个 A/B/C 或 A′/B′/C′ 批次：

1. 标准白恢复并确认基线。
2. 显示 source frame；等待 BUSY 完成和固定 2 s。
3. 显示 target frame；等待 BUSY 完成。
4. 在 5 s、60 s、10 min 拍照；这 10 min 内保持统一的 powered-idle 条件，不切继电器。
5. 记录每格颜色、均匀性、旧态轮廓、边界、左右差异、电流和温度。
6. 执行一次标准白恢复并人工确认。
7. 到达批次安全停点；下一批必须由操作者继续，不自动串行。

正式覆盖量：3 个正向批次 + 3 个镜像批次，每批 `source→target→white`，共 **18 个可见动作**。
时间点拍摄不是可见动作。现有 8×8 结果是先导证据，不计入这 18 个新测试台正式动作。

### 6.5 候选判定和重复

初筛只标记，不立即宣称新颜色：

- `H0`：落在既有 7 色组内；
- `H1`：可能只是不均匀/网点/残影造成的假色；
- `H2`：与最近已知色有稳定差异，待镜像和重复；
- `H3`：出现电气、BUSY 或恢复异常，立即禁用并封存。

只有正向和镜像都为 H2 的 pair 才进入确认。先重复 3 次；仍成立后再做 10 次重复、
0.5/2/10/60 s dwell 和 1 h/24 h 保持。1 h/24 h 必须在 manifest 中固定为
`powered_idle` 或 `safe_power_off`，两种保持模式不得混在同一统计中。

### 6.6 S2-2：三步序列不是默认全量队列

`7³=343` 条序列若按 16 格执行，需要 22 批；每批至少
`source→mid→target→white` 四个可见动作，即 **88 个动作**。若全量再做左右镜像，则至少
**176 个动作**，尚未计入重复和异常恢复。

因此默认流程为：

1. 只从 S2-1 的 H2 候选生成优先三步序列；
2. 每条候选的前态扩展、目标扩展和 alias 控制由 plan compiler 确定并完整列出；
3. 先运行一个不超过 16 条的批次，人工评审后再决定是否扩展；
4. 若 S2-1 没有 H2，阶段二以“未发现新增可重复单像素状态”结束，不穷举 343；
5. 只有用户明确选择“建立完整状态数据库”时才生成 343 全量 release，且必须另行预算屏耗和时间。

裁剪不是删除数据：所有未执行序列必须在最终报告中列出 `NOT_RUN` 和确定性裁剪理由。

## 7. 逻辑分析仪到位后的流程

### L0：设备自测

1. 封存型号、硬件序列号、软件版本和探头定义。
2. 用已知频率方波和已知 SPI fixture 做 25/50/100 MS/s 自测；确认边沿、位序和时间基准。
3. 检查所有探头仅连接数字低压信号，共地方式正确；禁止连接 VGH/VGL/VSH/VSL/VCOM。

### L1：factory-OTP 基准捕获

在不改 LUT 的固件上捕获并分别保存：

1. 冷上电、复位和完整初始化；
2. 仅写显示 RAM、不刷新；
3. 全白刷新；
4. 7 色条刷新；
5. 正常 Power-Off/Deep-Sleep。

每个捕获至少保存原始工程文件、导出 CSV/二进制、通道定义、触发点、采样率、固件哈希和照片。
解析结果必须能与固件发出的命令/数据计数相互核对。

L1 可以在阶段二基线会话中附带完成，但逻辑分析仪未到位时不得伪造 `logic_file`；字段应明确为
`not_available`，不能写空文件冒充捕获。

## 8. 阶段三的逐门落地流程

### G3：命令和格式证据

L1 捕获普通 factory-OTP 初始化并不等于发现 RAM-LUT 写命令。进入 loader 实现前必须确定：

- 写入是易失 RAM，而非 OTP/NVM；
- 主/从 IC 的选择方式、命令、长度、表偏移和激活流程；
- 相位驱动枚举、时长单位、VCOM/border/温度分支；
- 是否可读回，以及读方向切换；
- 复位/掉电后的失效边界。

若捕获中根本没有 LUT payload，结论应是“当前路径使用 OTP，未观察到 host LUT”，而不是尝试
猜写相邻芯片命令。

### G4：未修改基线 LUT

只有取得完整原厂等价 RAM LUT 才执行：

1. OTP 路径基线 7 色条与白恢复，三次；
2. 冷启动后写入逐字节相同的 RAM LUT；支持读回时必须全量一致；
3. 相同帧、温度、SPI 和相机条件下重复三次；
4. 比较颜色、BUSY、电流、左右一致性和恢复。

无法读出或重建完整基线 LUT 时，G4 不可测试，阶段三停止；不能用“全 `00`/`FF`”或相邻型号
样例代替未修改基线。

### S3-C1：首轮候选

G4 通过后才允许：

1. 每个候选从已验证基线结构派生，保留禁止命令扫描和完整 SHA-256；
2. 首轮仅对已证明成对的完整相位做 `100%→95%→90%→85%` 的同比缩短；
3. 一次只改变一个转换项，不改电压、温度和其它表；
4. 小面积 active pixels 只减少参与像素数，不代表 LUT 本身局部生效；仍按全局 LUT 风险管理；
5. 初始每个会话最多 1 个候选，人工检查恢复后才能提高会话上限；
6. 每个候选独立授权、独立 claim，不自动重试，不在失败后自动写第二套 LUT。

出现 BUSY/电流/温度/左右失步/读回/恢复任一异常时，先正常停止命令；若有硬件危险则继电器
立即断电并锁存 `FAULT_LATCHED`。后续只允许人工检查和原厂基线恢复，不重跑候选。

## 10. 建议排期

### 现在至继电器到位

- 完成 D1–D4；不连接设备。
- 固定 42 pair 的批次/镜像规则、照片命名和结果 schema。
- 准备继电器信息采集卡，不实现猜测型号的真实串口命令。

### 继电器到位后的第一个半天

- 只做 R0–R2；不接驱动板和面板。
- 若默认态、枚举抖动或失联行为不合格，当天不进入 R3。

### 第二个半天

- 做 R3 驱动板无屏验收、残压和反向供电检查。
- 形成 real adapter identity 和 bench result；仍不刷新面板。

### 第一个阶段二真屏会话

- 只做 S2-0 三轮基线与白恢复。
- 最终继电器 OFF、物理切断确认、屏幕白态观察后安全停机。

### 后续阶段二会话

- 每个会话最多一个 A/B/C 或镜像批次；目标后保留 10 min 观察，再白恢复收尾。
- 六个正式批次完成后统一分析，不在现场临时生成三步序列。

### 逻辑分析仪到位后

- 先 L0 自测，再将 L1 捕获附加到一个已计划的 factory-OTP 基线会话。
- 只有 G3/G4 通过才另排阶段三；否则以协议证据不足正式结项，不做 LUT 写入。
